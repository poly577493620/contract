# 最终思考题技术方案

## 1. 外部大模型与银行合同数据

公网大模型不应成为默认路径。只有合同数据经过分类分级、最小化、脱敏和明确授权，并且供应商、传输加密、存储地域、留存/删除、二次训练、事件响应和审计条件都通过机构审批后，才可受控调用。否则应使用内网推理服务或私有化部署。

私有化部署还需要足够的推理算力、峰值容量、中文长文与结构化输出能力、模型压缩/升级策略、补丁与镜像治理、运维值守和灾备。模型能力下降时必须允许回退到规则与人工流程，不能为了“私有化”牺牲可验证性。

## 2. 从流水线升级到 Agent

Agent 只负责受控编排，工具应至少包括：文档校验、解析/OCR、条款抽取、证据检索、金额日期校验、规则引擎、模型复核、人工审批、报告签章和审计写入。每个工具声明最小输入、输出、权限、超时、幂等和失败恢复；高风险操作必须由人工确认，Agent 不能自行扩大文档范围或调用未批准端点。

典型流程是：解析工具产生不可变证据 → 检索工具按采购条款找合同候选 → 规则工具校验主体/数字/日期 → LLM 解释语义承接与隐含差异 → 人工仲裁冲突和低置信项 → 报告工具固化模型、提示词、规则和证据版本。

## 3. LLM 与规则引擎边界

LLM 适合：条款语义对应、长距离条件、隐含冲突、否定/例外、措辞等价和简洁解释。确定性规则适合：金额阈值、币种、日期区间、工作日/自然日、税率、必含条款、权限、状态机和审批条件。规则与模型冲突时不能静默覆盖，应展示双方证据并进入人工复核。

## 4. 强监管环境的留痕与风控

生产系统需记录数据来源与授权、输入文件哈希、解析/OCR 版本、提示词/模型/规则版本、调用端点、时间、token、结构校验、人工修改、审批签章和最终去向。权限采用最小化与职责分离，敏感正文静态/传输加密，日志避免正文泄露并具备防篡改能力。

还应建立模型准入、变更审批、基准集、漂移监测、红队测试、异常告警、回退、内部审计和定期科技风险评估。任何自动化结论都必须有证据链、责任人和可撤销路径。本方案是工程设计讨论，不构成具体法律意见。
